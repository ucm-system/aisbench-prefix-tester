# UX 审计报告 — AISBench 前缀复用测试器

> 审计对象：`D:\pt-release\win-unpacked`（2026-09-21 最新包）+ main 分支源码
> 审计方法：pmaster（KANO 需求分类 / RICE 优先级 / 用户旅程）+ ui-ux-pro-max 规则库（可及性/表单反馈/布局栅格）
> 证据：`docs/screenshots/ux-*.png`（1440×900 全页 + 1024×700 窄屏）
> 范围说明：第二节为审计新增问题（24 项，其中 A1/A2 已按产品决策改写）；**第七节为用户反馈的 8 组问题的详细描述、根因与整改措施**，与《UX-REDESIGN.md》的布局方案一一对应。

**产品决策约束（2026-09-21，用户确认）：**
1. **「运行监控」不做常驻导航页签**。监控是上下文页：点击「开始测试」后自动跳转进入；或从「运行记录」页进入（运行中的行要有醒目标识）。独立页签没有意义。
2. **「数据集」页面裁撤**。数据集库对用户无意义；配置页的「复用已入库数据集」「生成数据集预览」等残留入口一并清理（SLA 探针内部复用数据集的机制不受影响，那不是 UI 功能）。
以下审计与重设计均以上述约束为准，涉及「恢复导航入口」的旧建议作废。

---

## 一、用户旅程结论（pmaster 视角）

目标用户是「性能/推理测试工程师」。核心 Jobs-to-be-Done：
1. **连上服务，快速发起一次可信的压测**（当前断点：默认参数过重、命名不可发现、校验无反馈）
2. **运行中知道“现在发生了什么”**（当前断点：图表点稀疏、无阶段标记、日志噪音）
3. **运行后拿走结论并横向比较**（当前断点：结果只在日志 ASCII 表里、对比入口深、SLA 拐点无可视化）

产品可用性主线未断（能跑通全流程），但「结果可信度呈现」与「防呆」两层基本缺失——这正是工具类产品的期望型需求（KANO：做得好才满意的那类），当前普遍未交付。

## 二、问题清单（24 项，均为本报告新增）

优先级定义：P0=阻断/数据可信，P1=高频痛点，P2=明显摩擦，P3=打磨。

### A. 全局 / 信息架构

**A1 [P1] 监控页的上下文入口需要补全（按产品决策：不做常驻页签）**
- 证据：目前「开始测试」后会自动跳转监控页 ✓；但运行记录页的行上没有「运行中」动态标识（与已完成的行视觉一致），运行中的 run 不突出；run 结束后顶栏提示一旦消失，未查看过的回放就没有引导。
- 整改：①记录页运行中的行加呼吸点徽标+「监控」主按钮置顶；②顶栏「有正在运行的测试」提示保留到该 run 被查看过为止；③「开始测试」跳转行为固化为主流程契约。

**A2 [P2] 数据集功能 UI 残留清理（按产品决策：裁撤数据集页）**
- 证据：配置页仍保留「复用已入库数据集」下拉与「生成数据集预览」按钮（后者在旧包中还会静默 400）；没有数据集管理页后这些入口指向不明。
- 整改：配置页第 2 区简化为一行说明「数据集按当前参数自动生成，随 run 落盘可追溯」；移除复用下拉与预览按钮；词表来源保留（它影响数据生成内容，与数据集库无关）。

**A3 [P2] 深链/刷新后无上下文与回退路径**
- 证据：hash 路由直接打开 `#/monitor/<id>` 时侧栏无高亮项、无面包屑；浏览器/应用内无「返回列表」动线。
- 整改：每个详情页顶部加面包屑（运行记录 / run_id）；侧栏按路由前缀高亮（monitor 归入「运行监控」）。

**A4 [P3] 品牌资产缺失**
- 证据：侧栏 logo 为文字「PC」，与应用无关联；favicon 404（浏览器控制台报错）。
- 整改：产出应用图标（前缀缓存隐喻：层叠块+命中高亮），输出 ico/png 多尺寸，替换侧栏 logo 与窗口图标。

**A5 [P2] 中英混排与术语不统一**
- 证据：图表标题「Prefix Cache Query Breakdown」为英文，其余全中文；「HBM 命中率 / Ext 命中率 / 综合」无 tooltip 解释口径（Δhits/Δqueries）。
- 整改：建立术语表（HBM→显存命中，Ext→外部缓存命中，综合→复合命中率），图表标题中文化，指标卡 hover 显示口径公式与采集来源（vllm:/ucm: 指标名）。

**A6 [P2] 键盘与可及性未覆盖**
- 证据：全部交互仅按鼠标路径设计；表格无键盘导航；自绘图表无 aria 标签；彩点图例仅靠颜色区分（色弱不可辨）。
- 整改：表单 Tab 顺序治理 + 焦点环样式；图表加 `<title>`/aria-label；图例加形状区分（实线/虚线/点线）。依 ui-ux-pro-max 优先级 1（可及性 CRITICAL）。

### B. 新建测试页

**B1 [P0] 「校验配置」无任何反馈**
- 证据：点击后无 toast、无红字、无成功标识（对照「探测」按钮有 ✓ 反馈）。ui-ux-pro-max Forms 规则：Submit Feedback 缺失属 High 严重度。
- 整改：校验通过→绿色成功条「配置可用，可开始测试」；失败→错误摘要条（可点击滚动至出错字段）+ 字段级红框与错误文案。统一 toast 组件。

**B2 [P1] 运行命名入口不可发现**
- 证据：唯一命名入口是多轮表格第一行「名称」格；列表页大量「run 2026/9/21 13:15:12」。pmaster：命名是回溯/对比的前置数据。
- 整改：表单顶部第一行放「运行名称」输入框（placeholder 给示例：「qwen3-8101-90%重复-c4」），轮次名称仍可单独覆盖；提交时若为空给出建议名并允许就地修改。

**B3 [P1] 无配置预设/模板**
- 证据：页头写「配置 · 预设 · 数据集」但页面无预设能力；每次打开回到 192.168.1.10:8000/input 32768 默认值；上次填写的配置不记忆。
- 整改：①表单草稿自动保存（localStorage，按最后输入恢复）；②「保存为预设」+ 预设下拉（内置：快速冒烟/标准测试/PD 分离）；③默认值改轻量（input 2048/output 32/data 16/conc 8），避免新手一上来压垮服务。

**B4 [P1] 数值输入无边界与联动校验**
- 证据：input_len 可填任意大值，与目标服务 `max_model_len`（探测可获取）无校验；output_len/data_num/concurrency 无上限提示；错误要跑到 ais_bench 阶段才暴露。
- 整改：探测成功后记录 max_model_len/max_num_seqs，字段失焦即时校验（input_len+output_len ≤ max_model_len），超限红字并给出建议值。

**B5 [P2] 「探测」结果信息一次性和未回填**
- 证据：探测成功仅一行小字「✓ 服务可达 · /metrics 可达 · 模型: qwen3」；不展示模型列表、上下文长度、是否 UCM；不回填采集端点。
- 整改：探测后渲染「服务信息卡」（模型、max_model_len、metrics 端点、ucm 检测、版本），提供「一键填入采集端点」按钮。

**B6 [P2] 采集端点文本框无逐行校验与测试**
- 证据：2 行小 textarea；格式错误只有后端报错；无「测试连通」按钮；PD 多端点场景要手填多行。
- 整改：端点 chip 化（回车添加、可删除），每行带可达性小圆点（自动 ping /metrics），保留批量粘贴。

**B7 [P2] 长度分布的参数区不可见即失效**
- 证据：选「高斯 mean±std / 均匀 min–max」后参数输入不明显，未填参数无提示，提交后行为不可预期。
- 整改：切换分布时内联展开对应参数输入并标必填；未填则校验拦截。

**B8 [P3] 轮次表格缺常用操作**
- 证据：无「复制上一轮」、无「恢复继承」快捷、删除行无确认；JSON 模式错误只有后端报错。
- 整改：行 hover 出现复制按钮；覆盖过的单元格提供一键清空回「继承」；JSON 模式前端先 parse 校验再提交。

### C. 监控页

**C1 [P0] 图表无 tooltip / 无缩放 / 无导出**
- 证据：自绘 SVG 无悬停数值提示；无法查看某时刻精确值；不能导出数据。工具类产品「取数」是核心 JTBD。
- 整改：所有图表加十字线 tooltip（时间+各序列值）；支持框选缩放与双击复位；提供「导出本 run 时序 CSV」（后端已有 JSONL，前端转存即可）。

**C2 [P1] 阶段边界与事件在时间轴上不可见**
- 证据：warmup→full 切换、cache reset、轮次切换在图表上无标记；命中率突变无法归因。
- 整改：阶段边界画垂直虚线+顶部小标签（R1 warmup / R1 full）；事件（reset 成败、SLA 探针切换）在时间轴打点。

**C3 [P1] 多轮运行的时序混在一条轴上**
- 证据：rounds>1 时所有轮数据连续画在同轴，无分隔。
- 整改：按轮分色或加轮次分隔带；图表图例显示轮次开关，可聚焦单轮。

**C4 [P1] KPI 卡无参照基准**
- 证据：命中率 83.3% 无「理论命中率 ≈89.992%」参照；TTFT 无 SLA 阈值线。
- 整改：命中率卡副行显示理论值与偏差；TTFT/吞吐卡支持叠加 SLA 参考线（读 SLA 页最近配置）。

**C5 [P2] 日志区缺搜索/过滤增强与 stderr 入口**
- 证据：只有 全部/WARN/ERROR 三个过滤 + 跟随滚动 + 导出 stdout；无法搜索 run_id/关键字；stderr 不可见；tqdm 进度行未折叠。
- 整改：增加关键字过滤与「折叠进度行」开关（正则 `Progress:|POST=|Calculating`）；stderr 单独 tab；导出支持 stdout/stderr/合并。

**C6 [P2] 断线/重连无状态提示**
- 证据：WS 断开后图表静默停更；仅侧栏「Sidecar ● 已连接」一处弱提示。
- 整改：WS 断开时监控页顶部出现黄色横幅「实时连接中断，正在重连…」，恢复后自动补拉缺失时序。

**C7 [P2] 「停止测试」无确认且终态区分弱**
- 证据：停止直接生效；停止后与失败在记录列表中颜色相近（灰 vs 红）。
- 整改：停止加确认弹层（说明将丢弃未完成轮次）；「已停止」用黄色徽标，与「失败」红色区分。

**C8 [P3] run 头部信息薄**
- 证据：只有 run_id/时间/状态/轮次；无耗时、无数据集摘要（条数/前缀/重复率）、无「导出报告」直达。
- 整改：头部第二行展示 关键参数 chips（模型/输入/输出/并发/重复率）+ 耗时 + 导出按钮。

### D. 运行记录页

**D1 [P1] 行内 4 个常驻操作按钮，删除红字每行可见**
- 证据：23 行 × 4 按钮（监控/详情/xlsx/删除），视觉噪音大；删除无二次确认，误触即删数据。
- 整改：行 hover 才浮出操作；删除走确认弹层（输入 run 名或二次点击）；顶栏批量操作保留。ui-ux-pro-max：破坏性操作必须可逆/需确认。

**D2 [P2] 过滤维度不足**
- 证据：只有 手动/SLA/全部 + 搜索框；无状态筛选（失败/已完成/已停止）、无时间范围。
- 整改：筛选条增加「状态」多选 chips；记录>50 条启用分页或虚拟滚动。

**D3 [P2] 详情抽屉遮挡工具栏且导出被锁在抽屉里**
- 证据：抽屉打开后「对比所选/删除所选」被拦截无法点击；导出按钮只在抽屉内。
- 整改：抽屉改为右侧 Drawer（固定 480px，带遮罩，ESC/点遮罩关闭），不覆盖顶部工具栏；列表行内保留快捷导出。

### E. 对比分析页

**E1 [P2] 空状态与结果区缺少结构**
- 证据：未对比时右侧整片空白仅一条提示；对比后指标表/每轮矩阵/DP 矩阵/配置 diff 全部纵向堆叠在下方，无锚点。
- 整改：结果区加 tab 锚点（指标总览/逐轮对比/DP 矩阵/配置差异）；空状态给出图示化引导。

**E2 [P1] 对比结果无可视化**
- 证据：只有表格 + Δ%（abs/pct/good 三色），无柱状对比图；pmaster 视角：对比的价值在「一眼看出差异」。
- 整改：核心指标（TTFT P50/P90、吞吐、命中率）渲染成对柱图（run A vs run B），delta 标注在柱顶；多 run 用分组柱。

**E3 [P2] 练习轮排除逻辑不透明**
- 证据：「排除练习轮」默认勾选，但列表里练习轮标签弱（小灰字），用户不知道某些 run 为何「选了却不参与」。
- 整改：被排除项在列表中半透明+「已排除」徽标，悬停说明原因；顶部显示「已排除 N 个练习轮」。

### F. SLA 页

**F1 [P1] 调优过程无进度可视化**
- 证据：开始后仅表格逐行追加探针行；无「当前并发 / 二分区间 / 预计剩余」，无醒目取消入口。
- 整改：结果卡顶部加进度条与阶段文案（「爬升中 c=32」「二分 [64,128]」）+「停止调优」按钮；探针行实时高亮当前行。

**F2 [P0] SLA 结果无「并发-延迟」曲线**
- 证据：探针表只有数字；产品的核心结论（拐点在哪）需要看图。
- 整改：结果区渲染 双轴曲线（x=并发，左 y=TTFT P90/TPOT，右 y=吞吐），SLA 阈值画横线，命中区间绿色填充，拐点标注「SLA 内最大并发 = N」。

**F3 [P2] 历史调优选中态与详情联动不清**
- 证据：点击历史行加载详情，但结果卡是否被覆盖、选中了哪一行无视觉反馈。
- 整改：历史行选中高亮；结果卡标题显示「查看：2026/9/21 07:57:06」并给「返回最新」。

### G. 设置页

**G1 [P2] 采集间隔两处配置，生效关系不明**
- 证据：设置页有 2s/5s/10s/30s；新建测试配置里也有 collection_interval；谁覆盖谁无说明。
- 整改：设置页改为「新 run 的默认采集间隔」，run 内不可改；在两处互相标注来源（「默认值，单次 run 可在新建测试覆盖」）。

**G2 [P3] Tokenizer 资产注册后无管理列表**
- 证据：注册输入框+按钮，注册成功后在哪看到/删除不可知。
- 整改：注册下方列出已注册目录（含来源：内置/本机扫描/手动），可移除、可测试加载。

**G3 [P3] 重启 Sidecar 无确认与进行中状态**
- 证据：点击即重启；重启期间页面无反馈，恢复无提示。
- 整改：确认弹层 + 按钮进入 loading + 完成后 toast；若活动 run 存在则警告「将中断当前 run」。

### R1 用户复检反馈的 4 个问题（全部复现，含根因）

### R2 复审新发现问题

## 七、用户反馈问题详述（8 组，2026-09-21）

> 每组按「现状与证据 → 影响 → 根因 → 整改措施」展开，编号 U1–U8，供排期与验收对照。整改的布局级方案见《UX-REDESIGN.md》§6。

### U1 模型目录与预置 tokenizer 的关系混乱（新建测试页）

- **现状与证据**：「模型目录（tokenizer 来源）*」输入框为空（只有占位符 `D:\Models\Qwen3-32B`），右侧「或选择预置 tokenizer」下拉却默认选中 `GLM-4.7-Flash（local）`；两个控件一左一右、标签基线不齐，看不出谁是生效值。实际生效的是下拉里的 GLM 预置——与压测目标 qwen3 不一致，理论命中率计算用了错误词表。
- **影响**：词表错配 → 随机词表生成与 token 数换算偏差，命中率口径失真；且用户毫无感知。
- **根因**：两个字段是独立 state，无互斥约束；预置下拉有默认值而目录框为空，UI 未表达「当前生效来源」；控件顺序把次要（预置）放在右侧与主字段并排。
- **整改**：①改为单一「tokenizer 来源」选择器：选项为「预置：Qwen3-0.6B / Qwen3-32B / GLM… / 本地目录…」；选「本地目录」时展开路径输入框，选预置时禁用并隐藏路径框（互斥，而不是并排两控件）。②下拉放左侧作主控件。③默认值策略：探测到模型名后自动匹配同名预置（qwen3→Qwen3-0.6B 匹配不到时给提示），无匹配则默认「本地目录」并要求必填。④在控件下方实时显示「当前生效：Qwen3-0.6B（local）· 词表 151k tokens」。

### U2 词表来源与自定义词表文件关系不清（新建测试页）

- **现状与证据**：一行内并排「词表来源」下拉（gsm8k 文本（tokenizer 词表）/ tokenid 精确模式）与「自定义词表文件 vocab.txt（可选，每行一个词）」输入框，右侧再挂「理论命中率 ≈ 89.992」。三个信息没有主从说明，用户无法判断：自定义文件和下拉是什么关系？选 tokenid 模式文件还有效吗？
- **影响**：数据生成内容不可预期；「可选」字样让用户以为是高级项随手略过，实际选了 gsm8k 文本模式它根本不生效（或相反），命中率口径解释不清。
- **根因**：两个维度（词表类型、词表内容来源）被压缩成两个并列控件；缺少模式-参数联动说明。
- **整改**：①改为单选卡两选一：「gsm8k 文本（用 tokenizer 词表拼自然语言片段）」/「tokenid 精确（词表=token id 区间，精确控制编码长度）」，选中项下方内联展示该模式的参数（gsm8k 模式：无额外参数；tokenid 模式：vocab 文件或 id 区间输入 + 说明「每行一个词或起-止 id」）。②「理论命中率」移到摘要卡，并 tooltip 说明公式（repeat_rate 与 block 对齐的估算）。③每个模式带一句白话解释与示例文本预览。

### U3 采集端点不联动、重复填写、URL 场景无解（新建测试页）

- **现状与证据**：服务地址/端口填了 `203.0.113.10:8101` 后，采集端点文本框仍是默认的 `192.168.1.10:8000 192.168.1.10:8001`，不联动；单机混部（推理端口=采集端口）也要再填一遍；「完整 URL」字段与地址/端口三者的优先级无说明，URL 场景下采集端点填什么更无从判断。
- **影响**：漏改/错填 → 指标采不到，监控页全 0 且无提示；多填一遍是纯摩擦；URL + 多端点组合无文档。
- **根因**：端点框是独立 state 初始为写死的示例值；无派生逻辑；URL 字段是后加的，未与地址/端口/端点做一致性设计。
- **整改**：①默认联动：端点框为空时实时跟随 `地址:端口`（占位符显示灰色跟随值「将使用 203.0.113.10:8101」）；一旦手动编辑则显示「已手动覆盖 ✕」可一键恢复联动。②选「完整 URL」时，地址/端口折叠为只读解析摘要（scheme/host/port 自动回显），采集端点占位符提示「默认取 URL 的 host:port，可添加多端点」。③端点 chip 化 + 逐行 /metrics 可达性小圆点（复用探测逻辑，间隔轮询）。

### U4 摘要与体检空置、开始测试位置、小屏溢出（新建测试页）

- **现状与证据**（ux-config.png / ux-config-narrow.png）：右侧「摘要与体检」栏 1440px 下被压成 ~175px 窄条，文字全部截断（「输入 / 输出」值显示不全），栏内仅 7 行摘要，下方大片空白直到页底；「▶ 开始测试」埋在页面最底部右侧，校验/重置也在最底下；1024px 窄屏下右栏被挤出视口，表单横向溢出出现横向滚动条，只能拖动或最大化。
- **影响**：主要操作按钮与反馈信息分离在长表单两端；填写过程中摘要不实时可见；小笔记本（1366×768/1024）基本不可用。
- **根因**：布局是「固定右栏 + 左侧长表单」两栏，右栏宽度用固定 minmax 且未做响应式降级；操作按钮组放在表单流末尾而非粘性定位；栅格未用 `minmax(0,1fr)`，输入框 min-width 导致窄屏横向溢出。
- **整改**（对应 REDESIGN §6.1）：①右侧栏改为 **sticky 摘要卡（320px）+ 底部吸附的操作区**，「校验配置」「开始测试」固定在侧栏底部与表单当前视口同步可见，不再随滚动消失；摘要值实时联动。②<1100px 时右栏降级为表单顶部的横向摘要条，操作按钮 sticky 吸底。③全部栅格改 `minmax(0,1fr)`，消灭横向滚动。

### U5 监控页图表与日志区布局/数据问题（5 个子项）

- **U5.1 一行两图宽度不一致**
  - 证据（ux-monitor.png）：队列深度卡明显宽于 KV 利用率卡，且 KV 卡 canvas 不撑满容器，右侧留白；延迟趋势卡同样问题。
  - 根因：图表卡未用等分栅格（无 `repeat(2, minmax(0,1fr))` 约束），SVG 按内容宽度渲染而非容器 100%。
  - 整改：图表区统一 12 列栅格，每行两图各 6 列等宽等高（280px）；SVG `width=100% height=100%` + viewBox 自适应；容器 resize 监听重绘。
- **U5.2 队列深度图头下方空白、图例挤在右下**
  - 证据：图头（标题+5s 采集 badge）之后绘图区上缘留白明显；running/waiting/swapped 图例贴着卡片右缘底部，与标题脱节。
  - 整改：图例统一放图头右侧（标题左、图例右、同一行基线）；绘图区上不留白；y 轴从 0 基线起。
- **U5.3 折线只有几个点，反映不了状态变化**
  - 证据：60 秒的 run 吞吐/命中率曲线只有 2-3 个孤立尖峰；延迟趋势同样。
  - 根因：采集固定 5s 且样本只写入轮询成功时刻；请求活跃窗口仅 ~10s，与采样窗口错开后曲线退化为脉冲；阶段内不足 5 点仍画平滑折线，视觉误导。
  - 整改：①自适应采样：检测到 running>0 或请求窗口内提到 1s，空闲回落设置值；②少于 8 点时改画**阶梯线 + 事件点标记**（不插值）；③阶段边界垂直线（见 C2）。
- **U5.4 队列深度一直 0**
  - 证据：回放视图 running/waiting/swapped 全程 0（同一次 run 的实时视图曾出现过 running≈5 的尖峰，两处渲染不一致）。
  - 根因：采样与请求窗口错开（同 U5.3）+ 实时（WS 推流）与回放（JSONL 重放）两条数据路径的 gauge 合并逻辑不一致（实时取 max 合并，回放按样本直读），需统一。
  - 整改：统一「实时=回放」数据源：WS 只推增量样本、图表状态机始终从同一条样本序列构建；回放时按 1s 重采样补齐 gauge 曲线；验收标准=同一 run 两种模式曲线一致。
- **U5.5 Breakdown 饼图显示 100.0% 与实际命中率矛盾**
  - 证据：HBM 83.3% / Ext 0.0%，环形图中心却是「100.0% 命中率构成（阶段快照）」，且中心文字与 caption 相互截断。
  - 根因（已定位）：`charts.tsx:67` Donut 中心值 = 各扇区值**求和**；扇区是命中构成占比（HBM 占命中的 100%），恒和为 100——中心显示的是「构成之和」，caption 却写「命中率构成」，必然被读成命中率 100%。
  - 整改：中心改显**综合命中率**（与 KPI 卡一致），caption 改「命中构成（HBM/Ext 占比）」；非 UCM 时隐藏 UCM 带宽图与 ⚠ 横幅，收进「指标说明」。中心文字与环半径留白校验，禁止截断。
- **U5.6 实时日志区太小**
  - 证据：日志面板高度固定约 200px、与「DP 域明细」并排只占半宽，长日志根本看不过来。
  - 整改：日志区改全宽独立区块，高度可拖拽（默认 360px，范围 240–600px，记忆用户偏好）；补关键字搜索、折叠进度行、stdout/stderr 切换（见 C5）。

### U6 对比分析：操作按钮沉底

- **现状与证据**：run 选择列表在左栏纵向排满 20+ 项，「排除 warmup/排除练习轮」与「▶ 开始对比」在列表最底部，选中两个后必须滚动到底才能点击；右侧结果区整片空白只挂一条提示。

- **根因**：操作控件放在列表流内而不是粘性容器。
- **整改**：顶部粘性操作条：`已选 chips [A ×][B ×] | 排除选项 | [▶ 开始对比]`（常驻可点，选满 2 个即高亮）；结果渲染在右侧主区；空状态给图示引导。被排除的练习轮半透明+徽标。

- **影响**：调优结果（页面的产出物）视觉权重最低；历史信息不可读；中断态没有解释。

- **整改**（对应 REDESIGN §6.5）：改为上下结构——上：配置卡全宽（目标 6 字段一行 + SLA 条件 + 并发范围 + 开始按钮）；下：结果区全宽 = 进度条（爬升/二分阶段+停止按钮）→ 并发-延迟双轴曲线（SLA 线+拐点标注，F2）→ 探针表；历史调优表列宽固定、说明列 ellipsis+悬停 tooltip+点击行加载详情并高亮；中断任务的结果卡显示状态徽标+中断原因，而非裸「—」。
